- **Before and after on the same corpus and judge:** the original ranking scores

## Why the shared database fails

It has no block that offers a subscription with a saving: its "subscribe" hits
are newsletter forms, menus and FAQs. Its block text was also captured when the
crawler kept only 400 characters, which cuts a buy box before its purchase
options. Recapturing and re-importing subscription stores fixes the data;
nothing in ranking can.

## Bugs found and fixed on the way

1. **Every multi-word search failed on a cold server** (`malformed array literal`,
   HTTP 503): postgres.js serialises `sql.array()` only after a connection has
   fetched array types, which never happens first with `prepare: false`. All
   array parameters are now Postgres literals (`pgArray`, web and platform).
2. **Typo correction rewrote real words**: "badge" → "bad", "picker" → "picked".
   A correction must now be a typo away (1 edit, 2 from eight letters).
3. **Design words never match copy**: "picker", "badge" appear in no block. A
   query naming a taxonomy block type (typos included) now searches that type
   (as tagged) or the copy that marks it; if nothing matches, the literal words.
4. **Search saw only 400 characters of each block**: the crawler now keeps 2,000
   (the API still serves 400). Manifest contract text updated in `docs/CONTRACTS.md`.
5. **Tagged block types were missing from the typo vocabulary** (migration 0007).
